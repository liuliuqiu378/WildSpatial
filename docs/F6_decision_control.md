> **和 P1/P2 的关系**：P1/P2 是这些模块的**真实跑通**；本篇是**讲原理**，读 P1/P2 前先读本篇就不懵。

## 0. 先说人话：世界模型 ≠ 动作

想象你眼睛看到了房间布局（墙在这、人在那），但你还得决定**抬腿往哪迈、迈多大步**。

```
感知（前面学的）          控制（本篇）           动作
─────────────          ───────────          ─────
像素 → 3D 世界    →    "往哪走、怎么动"   →   轮子转、机器人动
（M0–M9, F0–F5）        （本篇 F6）            （P1/P2 实跑）
```

**一句话**：感知回答"世界长什么样"，控制回答"那我该怎么办"。
两者之间的交接物，就是下节的 **WorldModel（世界模型）**。

## 1. 感知与控制的接口：WorldModel（衔接 §3.7）

> **目的**：让"感知"和"控制"彻底解耦——控制代码永远只读 WorldModel，不关心它是 M7 检测器给的、还是仿真真值给的。

### 1.1 WorldModel 里装什么

| 字段 | 含义 | 谁填 | 例子 |
|---|---|---|---|
| `ego_pose` | 机器人自身位姿 (x,y,θ) + 速度 | SLAM/里程计 | "我在 (0,-3)、朝北" |
| `occupancy` | 占据栅格（每格被占概率 0~1） | 深度/激光建图 | 墙=1、空地=0 |
| `obstacles` | 动态障碍列表（位置 + 速度 + 预测轨迹） | M7 检测+跟踪 | "行人@(2,1)，以 0.35m/s 向北" |
| `goal` | 任务目标点 / 语义指令 | 任务层 | "去 (0,3.8) 送货" |
| `confidence` | 每个格子/物体的置信度 | 感知栈 | "前方未知区域，置信度低" |

### 1.2 为什么这个接口是"分水岭"

§3.7 的核心结论：**Stage 2（决策控制）只消费 WorldModel，不 care 它怎么来的**。
所以——

- 仿真里用 `/world/default/pose/info` 真值 + 已知坐标填 WorldModel → 控制完美跑通（咱们 FPV demo 就是这么干的）；
- 真机里换成 M7 检测器填**同一个 WorldModel** → 控制代码一行不用改，只比"真值 vs M7"的差距。

> **🏭 实际应用**：工业级机器人（ROS2 Nav2）就是这套思路——感知插件往 `costmap` 里写占据信息，规划器只读 `costmap`。
> 你只要遵守接口，换个激光雷达、换个检测器，导航栈不用重写。

## 2. 把世界变成"能走的地图"：占据栅格与代价地图

> **目的**：把上一节的 `occupancy` 从"一堆 3D 点"压缩成"机器人能直接做路径搜索的 2D 栅格"。

### 2.1 占据栅格 OccupancyGrid

把地面画成方格纸，每个格子标"被占概率"：

```
■ ■ ■ ■ ■ ■        ■ = 占据(墙/障碍)   空格 = 自由
■       ■          → 机器人只能在空格里走
□ □ □ □ □ □
```

**直白讲解**：世界本是连续的三维，但规划算法喜欢"离散格子"——因为它能像走迷宫一样搜路。
把每个格子标上"能不能走"，问题就从"在无限连续空间里飞"变成"在有限格子里挑一条路"。

### 2.2 代价地图 Costmap（栅格 + 膨胀 + 语义代价）

占据栅格还不能直接用——**机器人有体积**，贴着墙走会蹭到。于是加一道"膨胀"：

```
原始障碍:     膨胀后(机器人半径外包络):
■                ▓▓▓
              ▓ ■ ▓      ▓ = 禁区(离墙一个机身宽)
              ▓▓▓
```

- **占据层**：真障碍在哪；
- **膨胀层**：障碍周围"机器人半径"范围内也标危险；
- **语义代价层**：比如"草地能走但慢、台阶禁行"——不同区域不同代价。

**真实图**：TB3 在 Gazebo 里 LiDAR → 膨胀 → costmap 的概念图：

![P2 TB3 costmap：LiDAR→膨胀→代价地图](../experiments/P2_tb3_nav2/figs/costmap_concept.png)

> **🏭 实际应用**：ROS2 `nav2_costmap_2d` 就是工业标准实现。你调的"膨胀半径"本质上是在说"我的机器人多大、要离障碍多远"。

## 3. 全局规划：从 A 到 B 走哪条路（图搜索）

> **目的**：在代价地图上，算出一条从"当前位置"到"目标"的**全局最优/最低代价路径**。

### 3.1 方法原理（专业）

- **Dijkstra / NavFn**：从起点向外" flooding "，每个格子记"到起点的最小累积代价"，到目标回溯成路——保证最短路但慢（全图扩散）。
- **A\***：加一个"到目标的直线距离启发式"，只往目标方向搜，快得多。本质 = Dijkstra + 方向感。
- 在栅格上，移动代价 = 格子代价 + 转弯惩罚。

### 3.2 直白讲解

类比**高德地图规划路线**：它不在真实马路上逐厘米试，而是在"路网图"上搜"耗时最短"的路径。
机器人也一样——在代价地图这张文氏图上，搜一条"总代价最低"的格子序列，就是全局路径。

**真实图**：手搓 A\* 在占据栅格上规划的路线（P1 服务机器人）：

![P1 占据栅格 + A* 全局规划](../experiments/P1_service_robot/figs/map_plan.png)

**工业级 vs 手搓**：同样任务，ROS2 Nav2 的 NavFn 规划器 vs 咱们手搓 A\* 的对比（P2）：

![P2 工业级 Nav2 规划器 vs 手搓 A*](../experiments/P2_ros2/figs/navfn_vs_p1.png)

## 4. 局部规划与动态避障：路上有人的时候

> **目的**：全局路径是"理想路线"，但真实环境会冒出没预料到的动态障碍（行人/车）。需要**局部实时重规划**。

### 4.1 方法原理（专业）

- **动态窗口法 (DWA) / 模型预测控制 (MPC)**：在"速度空间"里采样一堆 (v,ω)，预测短时轨迹，挑一条"不撞 + 贴近全局路径"的。
- **速度障碍法 (Velocity Obstacle, VO)**：把行人预测成"未来会占哪片区域"，机器人选一个避开该区域的 (v,ω)。
- **行人预测**：用匀速模型 / 跟踪器给行人 extrapolate 出短时轨迹（呼应 FPV demo 里 `PEDS` 的运动模型）。

### 4.2 直白讲解

全局规划是"我打算走这条道"；局部规划是"等等，前面有人，我**减速 / 绕一下 / 停住让他先过**"。

这正是咱们 FPV 送货 demo 里那几个工况的本质：
- **② 动态行人·停车让行** = 检测到行人在 1.3m 内 → 速度清零（VO 判定危险）；
- **① 静态障碍·绕行** = 离柱子 < 1m → 降速 + 转向绕开。

**真实图**：速度障碍法让机器人在行人逼近时减速（P1）：

![P1 动态避障：速度障碍法减速](../experiments/P1_service_robot/figs/dynamic_avoid.png)

**真实图**：行人距离 vs 避障指令的闭环（P2 动态障碍五层 pipeline 之一）：

![P2 行人距离 vs 避障指令](../experiments/P2_dynamic_obstacle/figs/ped_tracking.png)

**真实图**：感知 → 决策 → 控制的五层数据流（P2）：

## 5. 控制：把"走那条路"变成"轮子怎么转"（差速轮 + PID）

> **目的**：规划给的是"期望轨迹 (x,y,θ)"，机器人底盘只认"左右轮转速"。控制负责把两者翻译并对齐。

### 5.1 差速轮运动学（最小公式）

差速轮机器人（TurtleBot 这类）：左右两个轮子，转速不同就转弯。

```
左轮速度 vL, 右轮速度 vR, 轮距 L
→ 线速度  v = (vL + vR) / 2
→ 角速度  ω = (vR - vL) / L
```

**直白讲解**：像**轮椅 / 坦克**——左边转快、右边转慢，车就向右拐。反过来，规划只要 (v,ω) 两个量，
控制就拆成左右轮该转多快。这就是"高层指令 → 底层执行"的翻译。

### 5.2 PID：让实际轨迹跟上期望

规划说"往北走 1 米"，但轮子打滑、地面不平，实际可能偏了。PID 做的事：
- **P（比例）**：偏了多少，就使多大劲纠；
- **I（积分）**：一直偏，慢慢累加修正（消除稳态误差）；
- **D（微分）**：快纠到位时提前收劲，别冲过头。

**真实图**：差速轮按规划指令生成的控制序列（P1 服务机器人，38 条控制指令）：

![P1 差速轮控制指令序列](../experiments/P1_service_robot/figs/control_cmd.png)

> **🏭 实际应用**：PID 是控制界的"hello world"，从洗衣机到无人机到火星车都在用。
> 你不需要发明新控制器，先吃透 PID + 差速运动学，就能让机器人真的动起来。

## 6. 兜底：建模不好时怎么不撞（衔接 §3.7.4）

> **目的**：§3.7 论证了"建模差 → 各种问题"。这一节是专业工程师和"只会跑 demo"的分水岭——**感知可能错，但机器人不能撞**。

三层保险（由外到内）：

| 层 | 名称 | 机制 | 依赖 | 作用 |
|---|---|---|---|---|
| ① | **不确定性感知** | costmap 带置信度；未知/低置信格子按"可能是障碍"处理 | WorldModel.`confidence` | 保守但不停车 |
| ② | **反应式安全层** | 读**最原始传感**（深度近距 / 激光 / bumper）做急停 | **不依赖** Stage1 语义结论 | **保命**：即使 M7 全错也能兜住 |
| ③ | **降级策略** | 感知置信度 < 阈值 → 减速 / 停车待确认 / 请求人工 | WorldModel.`confidence` | 优雅失败：把"做错"变"不做" |

**直白讲解**：
- 第 ① 层是"聪明地保守"——不确定就当障碍绕，慢但不停；
- 第 ② 层是"最后的安全绳"——它**跨过感知的语义判断**，直接看"前方 30cm 有东西没"，有就急停。这一层哪怕 M7 完全幻觉也能保命；
- 第 ③ 层是"认怂"——真看不清就停下喊人，总比乱撞好。

> **核心结论**：难点在感知（Stage 1），但**控制的鲁棒性可以独立保证**。只要第 ② 层在，感知差顶多"走得蠢/停住"，不会"撞上去"。
> 这是你能写进简历、也是真实产品必须有的工程素养。

## 8. 收尾：感知控制专业人士的能力模型

把前面所有模块串起来，一个"感知控制专业人士"应该能回答这 8 个问题（✅ = 本教程已覆盖）：

| # | 能力 | 对应文档 |
|---|---|---|
| 1 | 像素怎么变成 3D？（投影/深度/重建） | F0–F2, M0–M2 |
| 2 | 什么环境下会崩、为什么？（失效归因） | M3, M5 |
| 3 | 前馈模型 / 融合怎么补洞？ | M4, M6, M7 |
| 4 | 怎么端侧部署？ | M8 |
| 5 | **感知结果怎么交接给控制？（WorldModel 接口）** | **本篇 F6 §1 / §3.7** |
| 6 | **怎么把世界变成可走的地图？（costmap）** | **本篇 F6 §2** |
| 7 | **怎么规划 + 避障 + 控轮子？（规划/VO/PID）** | **本篇 F6 §3–5 / P1/P2** |

**🎯 一句话总结**：感知让你"看懂世界"，控制让你"在世界里行动"，**WorldModel 接口 + 兜底分层**是两者之间的工程骨架。
缺了控制，你只是个"会看不会动的视觉工程师"；补齐本篇，你才是能交付机器人的**感知控制专业人士**。
