# F5 · 视觉 + 激光雷达（点云）融合：量产感知的主流范式

> 前四篇 F0–F4 讲的是「一套相机怎么理解世界」。但量产自动驾驶 / 机器人 **几乎不用纯视觉**——
> 它们几乎都挂一路**激光雷达（LiDAR）**。本篇讲清：**为什么必须融合、怎么对齐、怎么融合、边界在哪**。
> 定位：**通用基础知识**（一般场景、零公式门槛、引用领域标准 + 本项目可跑 demo）。

---

## 1. 目的：为什么相机不够，非要多一路激光？

先把两种传感器的**能力边界**摊开（这是全部融合动机的来源）：

| | 相机（视觉） | 激光雷达 / 深度（点云） |
|---|---|---|
| **给什么** | 「**有什么 / 长什么样**」——类别、纹理、颜色、开放词汇 | 「**在哪 / 离多远**」——公制 3D 几何 |
| **强项** | 语义理解极强（M7 的 OWL-ViT 能按自然语言找物体） | 距离精确（厘米级）、不受光照影响、可夜间/隧道工作 |
| **弱项** | **不直接给距离**（单目深度是相对的；双目/学习式深度有误差） | **语义弱**（一圈点很难直接说出「这是红杯子」） |
| **失效场景** | 低光/逆光/雾霾/无纹理（M3/M5 已证：几何法在这些条件下崩） | 雨雪反射、镜面/玻璃、远距离点稀疏；且**贵** |

**关键洞察**：两者的强弱**正好互补**——
> 相机补语义、激光补几何。把它们对齐到同一坐标系，就得到「**带语义的 3D 点云**」：
> 既知道「那是个红杯子」，又知道「在我左前方 2.3 米」——这正是机器人抓取/避障/自动驾驶需要的表达。

**本项目里的真实动机**：`P0` 的 `autonomous_driving` 项目（4Seasons 夜间数据）因为**没有深度**，
场景图步骤只能**诚实跳过**。这个"缺口"恰恰说明：**量产驾驶方案必须再挂一路激光雷达**，否则 3D 感知无从谈起。

## 2. 方法原理（专业）

### 2.1 传感器怎么"对齐"：相机-激光外参标定

相机和激光雷达装在车上的**不同位置**，要融合，先得知道彼此的**相对位姿**（外参 $T_{cl}$：laser→camera）。
标定就是求这个 $T_{cl}$，方法分两类：

| 类型 | 做法 | 特点 |
|---|---|---|
| **靶标法** | 用特制标定板（棋盘格 + 反光孔/ArUco），同时被相机和雷达看到 → 解 PnP | 精度高、需人工摆靶，量产下线标定常用 |
| **无靶标法** | 利用场景中的**边缘/平面**一致性（图像边缘 ↔ 点云深度不连续）自动优化 | 方便但精度略低、依赖场景 |

设雷达系下一点 $P_l$，转到相机系：$P_c = T_{cl} \cdot P_l$。

### 2.2 点云 → 图像：投影公式（融合的几何核心）

得到 $P_c = (X_c, Y_c, Z_c)$ 后，用相机内参 $K$ 投影到像素：

$$
\begin{bmatrix} u \\ v \\ 1 \end{bmatrix}
= \frac{1}{Z_c}\, K \begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix}
= \frac{1}{Z_c}
\begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}
\begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix}
$$

**只保留 $Z_c > 0$（相机前方）且 $(u,v)$ 落在图像范围内**的点——这就是"点云投到图像上"。
每个投上的点天然带一个**距离值 $Z_c$**，于是图像上就叠加了"每处多远"的公制信息。

### 2.3 三种融合架构（前融合 / 中融合 / 后融合）

| 架构 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **前融合**（Early） | 在**原始数据层**融合（点云 + 图像 → 统一体素/BEV 张量） | 信息损失最小、理论上最优 | 依赖严格时空同步/标定，难训练 |
| **中融合**（Mid） | 各自提**特征**后再融合（图像特征 ↔ 点云特征交叉注意力） | 精度与鲁棒性平衡，主流学界方向 | 需精心设计融合层 |
| **后融合**（Late） | 各传感器**独立出结果**，在**决策层**合并（视觉出 2D 框 + 激光出 3D 框 → 关联） | 解耦、容错好、易落地 | 信息利用不充分、需关联逻辑 |

> **工程现实**：量产量产车多用**后融合 + 部分中融合**——因为传感器可能失效、时间戳可能不同步，
> 后融合的**解耦容错**更安全（相机坏了激光仍工作）。

### 2.4 数据有了，怎么"看懂 3D"：3D 目标检测

融合后的 3D 数据要变成"可用的物体框"，代表数据集与流程：

- **KITTI**（自动驾驶经典基准，含相机 + 激光 + 3D 框真值）、**nuScenes**（多传感器 360°，含雷达/激光/相机）、**Waymo Open**。
- 经典方法线：**PointPillars**（点云 → 柱体 → 2D CNN）、**SECOND**（稀疏 3D 卷积）、**CenterPoint**（中心点检测）；
  多模态 **MV3D / AVOD / BEVFusion**（相机 + 激光在 BEV 空间融合）。
- 输出：每个物体的 **3D 框** `(中心 x,y,z, 尺寸 l,w,h, 朝向 yaw)` + 类别。

## 3. 直白讲解（类比）

把两个传感器想成两种职业的人：

- **相机 = 一个"懂行但眼神不好估距离"的鉴定师**：一眼能说出"这是红杯子、那是灭火器"，但问他"离你几米"只能瞎猜。
- **激光雷达 = 一把"精准但没文化"的卷尺**：能量出 2.31 米，但完全不知道量的是杯子还是灭火器。

**融合 = 让两人配对干活**：卷尺（激光）报出"2.31 米"的位置，鉴定师（相机）说"那个位置是红杯子"——
于是机器人得到一句话：**"红杯子，在我左前方 2.31 米"**。这才是它能伸手去拿的**指令**。

- **标定** = 让两人站在**同一套坐标**里说话（否则"左前方"对不上）。
- **前/中/后融合** = 两人**什么时候交换信息**：一开始就一起干（前）、各干一半再合（中）、各干完再对（后）。越早融合越强但越难协调。
- **3D 检测** = 最后把结果整理成"货架清单"：几个箱子、每个在哪、多大、朝哪。

## 4. 真实数据验证 + 效果展示（本项目可跑 demo）

**设置**：用**两套真实数据**验证「相机 ↔ 激光」融合几何：
1. **TUM `fr1/desk` RGB-D**：用真实深度反投影点云，验证投影公式 + 内参自洽。
2. **KITTI depth completion 真实 LiDAR**：用车载相机 + 真实激光雷达数据，验证在真实传感器上的融合形态。

两套数据各有使命：TUM 给**数学自洽**（0px 残差），KITTI 给**真实传感器**（真实 LiDAR 扫描线）。

### 4.1 TUM RGB-D 反投影：投影公式与内参自洽

**跑一遍**：
```bash
conda activate wildspatial
PYTHONPATH=src python scripts/m10_lidar_fusion_demo.py
```

**实测结果**（`experiments/M10_lidar_fusion/metrics.json`）：

| 指标 | 实测值 | 说明 |
|---|---|---|
| 点云总点数 | **255,190** | 由真实深度反投影所得（稠密） |
| 落入相机视场比例 | **100.0%** | 点云本就来自该相机 → 全部可见 |
| 稀疏 LiDAR 模拟点（视场内） | **4,000** | 按扫描线列间隔下采样，贴近低线束雷达量级 |
| **重投影残差** | **0.0000 px** | 3D→2D 投影与原始像素完全吻合 → **验证 K 自洽** |

![视觉 + 激光/深度 融合：TUM 投影闭环与带语义的 3D](../experiments/M10_lidar_fusion/figs/lidar_projection.png)

> **🖼️ 你看到的**：
> - **① 相机 RGB**：语义强（看得懂桌子、显示器），但**没有距离信息**。
> - **② 稀疏点云 → 图像投影**：把"激光点"投回图像，**颜色=距离**。注意它是**稀疏的竖直扫描线**（模拟真实 LiDAR），
>   不是稠密深度图——这正说明"激光补几何"：图像上每处都多了个**公制距离**。
> - **③ 图像 → 彩色点云**：给每个 3D 点赋上 RGB → 得到**彩色点云融合体**。
>   ②③ 是一对**互逆过程**，能自洽（残差 0px）说明内参/外参正确。

> **🖼️ 你看到的**：
> - **① Camera RGB**：真实车载相机视角，语义强，但没距离。
> - **② Real sparse LiDAR → image**：**真实 LiDAR 点**稀疏地落在路面、车辆、护栏上，按距离着色。

> - **③ Real dense depth**：多帧激光累积出的稠密深度真值，颜色=距离。
> - **④ Colored point cloud (top-view X-Z)**：给真实 3D 点赋上 RGB，得到"外观+几何"融合体。

> 现在 F5 同时保留 TUM（**数学自洽证明**）与 KITTI（**真实传感器验证**），
> 两套数据互相印证：投影几何不仅在数学上 0px 残差，也在真实 LiDAR 数据上成立。

## 6. 🏭 实际应用

- **自动驾驶 / 无人配送**：BEVFusion 类方案融合相机 + 激光做 3D 检测与可行驶区域（本篇 §2.4）。
- **工业 AMR / 仓储机器人**：激光建图定位 + 相机识别货品，抓取前用融合点云算出**抓取位姿**。
- **无人机 / 巡检**：相机识别缺陷（裂纹/锈迹），激光/深度量大坝/桥梁的**几何形变**。
- **AR / 手机 LiDAR**：iPhone LiDAR + RGB 做**场景网格重建 + 虚拟物体遮挡**（同一套投影几何）。
- **矿区 / 地下 / 水下**：相机在这些环境极易失效（M3/M5），**激光/声呐点云成为几何主源**——融合是刚需而非锦上添花。

> **本项目对应**：这就是 `M6`（融合思想）+ `M7`（语义）+ `M2/M4`（几何源）三者的**工程汇聚点**，
> 也是 `P0` 实战项目在"真实恶劣数据缺深度"时暴露出的、必须补齐的一路传感器。

---

## 7. 三条核心结论

1. **视觉与激光是"语义 × 几何"的互补对**，不是替代关系——相机给"是什么"，激光给"有多远"，融合才得到机器能用的 `{class, xyz}`。
2. **融合的几何地基是"标定 + 投影"**：先把两路对齐到同一坐标系（外参 $T_{cl}$），再靠 $K$ 做点云↔图像互投（本篇 demo 残差 0px 自洽）。
3. **恶劣环境让融合从"锦上添花"变"刚需"**：`M3/M5` 已证相机在低光/模糊/噪声下崩（VGGT 除外），此时**只有激光能保几何**——这正是量产方案的冗余设计逻辑。
