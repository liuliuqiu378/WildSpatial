- **ORB-SLAM2 单目**在 fr1/desk 上 ATE 约 **0.02~0.05 m**（但有回环检测 + 局部 BA + 共视图优化）。

**结论**：管线正确，几何链路通了。0.5m 的 ATE 是"没有后端优化"的合理代价。

## 三个真实踩到的坑（比 ATE 数字更有价值）

### 坑 1：帧间视差不足 → 初始化根本起不来
TUM 是 30fps，相邻帧位移很小。实测：

| 指标 | 帧 0→1 |
|---|---|
| RANSAC 内点率 | 97.7% ✅ |
| **视差角中位数** | **0.41°** ❌ |
| 三角化深度中位数 | 100 m（真实仅 1~2 m）❌ |

匹配质量很好，但**几何上不可解** —— 完美印证 M0 §6.2 的"小基线病态"。

**解法（同 ORB-SLAM）**：固定参考帧，等运动累积到中位视差 > 3° 再初始化。
本序列在第 3 帧满足。→ 参数 `init_min_parallax_deg`。

### 坑 2：深度检查写在了尺度归一化之前
初始化时 `t` 是**单位向量**，三角化出的深度可能是 100m 量级。
原代码拿它去比 `max_depth=20` 阈值，几乎全被误杀。
**必须先定尺度，再做深度合理性检查。**

### 坑 3：位姿指数爆炸（最严重）
无护栏时，一次 PnP 失败 → 回退路径用"上一帧位移"猜尺度 → 异常跳变逐帧放大：

| | 无护栏 | 有护栏 |
|---|---|---|
| RPE 平移 RMSE | **49,940 m** 💀 | 0.156 m |
| Sim3 尺度 | 0.0000 | 0.300 |

**解法（运动连续性护栏）**：
1. 单帧位移上限 `max_step_m`（默认 0.5m）
2. 不超过最近 N 帧位移中位数的 `max_step_ratio` 倍
3. 回退路径用**中位位移**而非上一帧位移，并 clip 到上限

> 📌 **这是最重要的工程经验**：VO 不是"估得准不准"的问题，而是"崩了能不能回来"的问题。
> 没有护栏的系统，一旦出现一次异常跳变就再也回不去了。

## 诊断曲线说明（figs/diagnostics.png）

每帧记录：特征数 / 匹配数 / 内点率 / 地图点数 / 跟踪状态。
**这些过程量比最终 ATE 更能定位失效根因** —— 它们是 M3 失效归因的数据源。

当前基线的特征：内点率均值 75%，但波动大（最低 61%）。
在恶劣环境下这个数字会掉到 20% 以下，届时 RANSAC 需要的迭代次数会指数爆炸
（见 `test_ransac_degrades_with_low_inlier_ratio`）。
